# 戰鬥計算與模型摘要

此版將可核對的觸發計數、擊殺與擊殺後承傷交給程式，保留未知互動的模型 fallback。修改在 `codex/custom-battles` 分支；本輪診斷直接載入分支程式，遊戲面板的背景 bridge 仍讀主專案，尚未合併或切換到此版。單純重開遊戲不會自動合併分支。

## 新增範圍

- 神氣制勝：讀取實際剩餘張數與全體傷害，計算支援牌打出後是否觸發、重設為 5；剛打出的神氣制勝不算自己的第一張，藥水不算牌。此傷害不是 Powered attack，不套用力量／易傷。首次施放仍是需重新讀局面的能力牌起手，沒有假裝搜尋器已模擬所有能力牌。
- 普通易傷、痛擊與雙重打擊：痛擊先造成傷害再上易傷，雙重打擊按每一擊計算與取整，逐擊扣格擋。切割、偏折只接受完整吻合的普通傷害／格擋描述。
- 噬屍蛞蝓飢餓：死亡使存活蛞蝓本次敵人回合被擊暈，並按當前顯示的 amount 增加力量。候選列出擊殺／擊暈對象、少承受的攻擊、剩餘能量與下一回合增加的力量；不把下一回合的力量風險當成零。
- 連續出牌：以 `combat_id` 記住敵人，送出下一張牌時才解析最新 `entity_id`。死亡後顯示索引重新編號，也不會打錯原目標；原目標已死時停止該序列重新決策。藥水隊列共用此目標身份核對。
- 已知神氣制勝計數的正常變化不再使候選隊列失效；額外狀態、抽牌、改費用等未預期變化仍中止隊列。模型提示以數值摘要取代已核對狀態的重複說明，仍保留未知規則。

## 精確性限制

API 卡牌傷害文字已含玩家修正並已取整。虛弱與目標易傷並存時，先讀取整後文字再乘易傷可能丟失小數；目前直接回 `combined_damage_rounding`，不聲稱精確擊殺。人工製品阻擋痛擊的易傷尚未模擬，回 `unmodeled_artifact_debuff`。紙蛙、殘酷、衰弱、反傷、復活、其他死亡觸發與未支援遺物仍需 fallback；部分估算明確標示未模擬效果。

候選只評估已支援的當回合效果，不是整場最優解。Haiku 仍看完整手牌與候選，此版沒有把 Haiku 改成只能選編號。

## 2026-10-12 驗證

全套 199 項 Python 測試通過，包含逐擊易傷取整、痛擊先後順序、虛弱／人工製品 fallback、五張牌觸發、候選計數保護、死亡後顯示 ID 重用與已死目標中止。`tests/fixtures/controlled-combat-triggers.json` 是本輪受控實機狀態，去除非必要欄位；它不是玩家最優決策標準答案。

零模型實機診斷：

1. A0 靜默獵手，神氣制勝與六張偏折、蛇之戒。施放能力後仍差五張；四張偏折沒有傷害、剩一張；第五張觸發 10 點全體傷害、重設五張。搜尋預測與實際敵人 HP 吻合。
2. A0 鐵衛，痛擊＋與雙重打擊＋。痛擊後預測可擊殺已易傷蛞蝓，實際擊殺；存活蛞蝓被擊暈並增加 4 力量（A0 顯示量，不硬寫成 A10 的 5）。過完敵人回合，HP 80→80，吻合零承傷預測。
3. A0 鐵衛，痛擊＋、雙重打擊＋與切割。最後一張牌指定原本第二隻蛞蝓；第一隻死亡後第二隻由 `CORPSE_SLUG_1` 變為 `CORPSE_SLUG_0`，隊列按相同 combat_id 解析新 ID，切割成功使該敵人 HP 25→19。另一次控制案例未發生重新編號，不將它冒充此項證明。

原始診斷記錄在忽略的 `vakuu/button-runtime/lab/combat-trigger-live.json`。本輪沒有模型呼叫或完整戰鬥勝率比較。遊戲留在受控診斷戰鬥，沒有活躍 AI 控制器。

重播此前兩批的 344 個穩定玩家局面，新舊搜尋器均因未支援遺物回 `unknown_relic`；未據此宣稱減少模型呼叫。獨立的觸發摘要已能在先前神氣制勝敗局讀出「施放後還需五張、之後剩四張」的正確數值。下一步若要增加這些實戰局面的程式覆蓋率，應逐個核對未支援遺物，而不是移除保護。
