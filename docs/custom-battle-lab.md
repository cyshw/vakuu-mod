# 自訂戰鬥練習（初版）

執行 `python tools/battle_lab.py serve`，開啟 http://127.0.0.1:15528/。
遊戲必須載入此分支編譯的 STS2_MCP.dll，並先停下 AI 接手控制器。

在頁面選擇範例、編輯資源欄位與牌組清單後按「套用配置並開始戰鬥」，到遊戲視窗手動出牌。可以搜尋卡牌、增刪與修改升級次數，進階選項也能手改 JSON。「同配置再打一場」使用新的隨機種子與獨立記錄；不重現相同起手或敵人亂數。錄製過程不呼叫模型。

預設範例取自 [Spire Codex 的 v0.111.0／A10 鐵衛通關紀錄](https://spire-codex.com/runs/af89e3c82bb6f873)，24 張牌與 14 個遺物，包含惡魔形態＋與雙重打擊＋。力量成長是依牌組內容的推論，並非網站給出的流派分類。配置保存於 `tools/lab-presets/spire-ironclad-strength.json`；卡牌／升級／遺物使用最終配置，練習敵人為原紀錄的靈魂核心菁英，HP 調整成 80/80、藥水清空。這不是該樓層精確重現；原紀錄的 26 點傷害／5 回合只能作背景，不能當此局基準。沒有重新使用原對局的亂數。

資料使用網站文件化的公開 `/api/runs/list`、`/api/runs/shared/{hash}` 與 `/api/cards`，不需帳號憑證；卡牌搜尋目錄快取一天。完整原始回應只保存在忽略的本機 build 目錄，不提交玩家完整對局資料。

配置欄位：`character`、`encounter` 使用遊戲模型 ID；`ascension` 0–10；`act` 1–3；`floor` 全局樓層；`act_floor` 本幕樓層；`hp`、`max_hp`、`gold`；`deck` 是包含 `id` 與 `upgrades` 的清單（重複牌逐張列出）；`relics` 與 `potions` 是 ID 清單。空遺物／藥水清單會清空起始配置。先以頁面提供的鐵衛範例測試，再調整。

初版限制：牌組最多 100 張、藥水最多 3 瓶；遺物只接受頁面列出的 22 種，避免取得遺物時需要選牌的互動讓配置卡住。每次開局重新取得遺物，再套用完整牌組／升級／HP，避免卷軸、塗料等取得效果改變指定配置。不支援自訂遺物計數器、附魔牌、瓶裝指定牌或持續效果。樓層以測試用歷史項目設定；此局適合練戰鬥，不適合繼續走普通地圖。啟動使用遊戲 `shouldSave=false`，不取代普通存檔；API 拒絕替換其他正在進行的局。這不是精確 SL。

錄製期間一般玩法 POST 會被阻擋，仍可在遊戲 UI 操作。停止錄製後可再次使用一般 API。記錄存在 `vakuu/button-runtime/lab/<attempt>.jsonl`（不提交 Git），包含配置與種子、回合開始狀態、出牌／藥水／結束回合前後狀態、選牌暫停與實際選擇、戰鬥結束或手動停止。頁面開著時每秒保存新事件；重打前會停止並保存舊場記錄。若跳過頁面直接呼叫 `/api/v1/lab`，呼叫端必須自行保存舊場事件。遊戲端最多保留 1500 個事件，溢出會明確停止錄製。

## 離線比較

```
python tools/battle_lab.py compare PATH.jsonl --limit 5 --config codex:gpt-6.1-sol@low
python tools/battle_lab.py compare PATH.jsonl --limit 5 --config claude:haiku@low
```

這兩個配置各自需要可執行且已登入的 Codex／Claude Code CLI。比較最多 20 個已完成的操作，只比較第一步的牌索引與目標，或藥水槽與目標、結束回合；不向遊戲送指令。取消、失敗或无法核對牌／目標的步驟不會作為人類答案。選牌互動會被記錄，但初版不做選牌答案比較。

輸出 `<attempt>.comparison.json`，保存局面、人類操作、模型答案與差異。`approved=false` 固定作為待審候選，差異不能证明誰較好；仍需使用者檢視後才可人工納入 `tests/regression`。初版尚未提供頁面上的題目審核／匯入按鈕。

## 後續練習流程

依使用者要求，先由 AI 打，失敗或卡住才交給使用者；先停止控制器並保留狀態、模型答案與操作記錄，再分析搜尋、評分、執行或模型問題。頁面尚無自動轉交功能，現階段由測試流程操作。失敗後重新開局會改變亂數，不是原失敗局面的精確 SL。

後續配置依使用者最新偏好隨機挑選實戰局面，不固定流派；仍核對來源版本、取得時間與練習工具支援範圍，避免默默帶入後期卡牌或漏掉附魔等機制。

新增 `tools/lab-presets/spire-ironclad-slow-start.json`：同一 Spire Codex 通關來源的第 12 層幽靈船，依前 11 層紀錄重建 14 張牌（惡魔形態於第 7 層升級，其他尚未升級）、4 遺物、2 藥水、202 金幣與 41/80 HP。第 14 層才刪打擊，因此這裡保留 5 張打擊；第 12 層獎勵不預先加入。基礎牌占比高、成長需啟動，作為「蠕動」練習是我們的推論。原玩家此戰 5 回合、受到 22 傷害，並非新亂數下的標準答案。未重建遗物內部計數與原抽牌順序。

此配置已實機核對 14 張牌、4 遺物、2 藥水及 41 HP。來源歷史逐步重建校驗通過（牌組／升級／藥水／遺物／HP／金幣／敵人）；4 項 lab 離線測試通過。Haiku／low 在第 1 回合惡魔形態觸發干癟之手後，費用延遲更新造成狀態保護停止；保留原紀錄並在穩定局面續跑一次，沒有重開或改亂數。最後第 4 回合勝利，結束 33/80 HP，兩段共 13 個 API 操作、6 次模型呼叫、模型耗時合計 44.93 秒。這是有人協助續接的結果，不能算整場無中斷自動完成；費用延遲造成停止的問題尚未修正。記錄為 `haiku-slow-start-069e8a.jsonl` 與 `haiku-slow-start-069e8a-resume.jsonl`。停在獎勵畫面，未領取金幣或抓牌。結束 HP 含戰後治療，不能直接與來源 22 點傷害比較。

### 干癟之手結算修正

後續已修正 `wait_for_change`：持有干癟之手打出能力牌且剩餘手牌有付費牌時，等待實際免費效果，再等待原本 0.2 秒穩定窗口；超時明確停止，仍保留送出前的局面檢查。手牌已全免費或普通出牌沿用快速輪詢，不整體拉長等待。

173 項 Python 測試通過，新增延遲免費、效果缺失超時、全免費手牌維持速度三個案例。從來源已核對的第 11／12 層隨機抽樣，本次抽到第 12 層幽靈船；Haiku／low 無中斷勝利，6 回合、41 HP 進場、20 HP 結束。這場沒有打能力牌，不能用它證明干癟之手修正。

另做單步實機診斷：A0 五張牌含惡魔形態＋、打擊、防禦、痛擊、閃電霹靂，保留干癟之手；程序打惡魔形態後等待約 1.093 秒，確實讀到閃電霹靂費用變 0，再結束等待。0 次模型呼叫，未進行整場戰鬥；這是人工設計的診斷配置，不是來源實戰。原始讀取序列與結果保存於忽略的 `vakuu/button-runtime/lab/mummified-settling-live.json`；完整隨機場記錄為 `haiku-random-settling-fixed.jsonl`。目前遊戲留在此單步診斷局，沒有活躍接手控制器。

### 共通結算訊號

依目前遊戲 API，GameAction 的執行任务會 await 卡牌／藥水指令和觸發效果；ActionQueueSet.IsEmpty 與 ActionExecutor.IsRunning 可供判斷。新增戰鬥狀態頂層 `execution: {queue_empty, running}`，包含選牌 overlay，避免將仍可出牌的 is_play_phase 誤當作已完成結算。

新版控制器有此訊號時等待佇列空且執行任務停止，再繼續決策；選牌介面可以先處理，避免暫停中的動作永遠等不到完成。超時仍忙就安全停止，送出前也拒絕仍忙的局面。執行訊號不納入決策 fingerprint，避免只有任務狀態切換就觸發局面失效；沒有此訊號的舊模組仍使用穩定窗口與干癟之手 fallback。

178 項 Python 測試通過，包含長時間狀態不變後抽牌與能量效果才到達、選牌暫停、忙碌超時、fingerprint 相容及抽回同名同內容牌。C# Release 0 警告／0 錯誤。使用者手動關閉診斷遊戲後，已安裝新版 DLL 並重新啟動。

五種零模型單步實機診斷通過：防禦約 0.391 秒、聳肩無視抽牌約 0.453 秒、祭品抽牌並加能量約 0.406 秒、干癟之手隨機免費約 0.688 秒、堅毅＋選牌約 0.235 秒。選牌時 queue_empty=false／running=false，能繼續選擇；確認後約 0.594 秒回到佇列完成的戰鬥狀態。實測祭品打出後抽回另一張相同祭品，手牌簽章不變但 HP／能量已變；修正為以佇列完成訊號優先，避免仍被舊手牌檢查判成未結算。原始讀取序列（祭品、改費用、選牌）保存在 `common-settling-live.json`；普通出牌與抽牌的首次成功結果記在終端輸出與本文件。尚未核實的新版本、多玩家佇列或其他背景動畫，不宣稱全都受此訊號涵蓋。

從目前兩個已核對來源範例隨機挑選，抽到第 12 層慢啟動配置，attempt `feea41b556fc45eea898d55774037da2`。Haiku／low 7 回合勝利，41 HP 進場、20 HP 結束，26 個成功 API 操作、0 失敗、8 次模型呼叫（包含最後獎勵畫面的建議）、模型耗時合計 60.56 秒，沒有局面變更中止或人工续接。連續出牌與兩種藥水（明耀酊劑、熔爐的祝福）皆成功；升级手牌後重新決策，沒有繼續執行過期牌組計畫。來源配置與模型／操作記錄分別為 `common-settling-random-config.json`、`haiku-common-settling-random.jsonl`，摘要為 `haiku-common-settling-summary.json`。停在獎勵畫面，沒有領取金幣或抓牌，沒有活躍控制器。不同亂數與不同戰術下的血量、回合、模型次數不能當作新版勝率或節省額度的證明。

### 隨機關卡測試

依使用者要求，從同一來源的第 2、5、6、8、11、12、15 層戰鬥隨機抽樣；此範圍內的前置取得／刪牌／升級／藥水使用紀錄及遺物均可核對、可由練習工具套用，不代表全遊戲所有關卡。此次抽到 A10 第 2 層淤泥旋螺（SLUDGE_SPINNER_WEAK），進場 64/80 HP、12 張牌、燃燒之血與奧術卷軸、無藥水，重新生成亂數；attempt `7fd912b31e7449ef9770118d7610badb`。

Haiku／low 無中斷勝利，4 回合，結束 53/80 HP；12 個成功 API 操作、0 失敗、4 次模型呼叫，模型耗時合計 29.86 秒。同場模型規劃後由程式連續出牌，沒有人工續接。配置、完整記錄與摘要為 `random-encounter-config.json`、`haiku-random-encounter-01.jsonl`、`random-encounter-summary.json`（本機 runtime，不提交）。停在獎勵畫面，沒有領取獎勵或抓牌，控制器已停止。結束血量包含戰後治療；單場結果不能證明隨機關卡整體勝率。

使用者接著要求提高蠕動局權重。新增 `python tools/random_lab.py`，只抽樣並輸出配置，不操作遊戲或呼叫模型；`--preview` 顯示機率。僅適用上述已核對來源／樓層，讀取本機原始來源快取。權重為 1，加上低血量（<=50% 加 2、<=75% 加 1）、來源實際受傷（>=15 加 2、>=8 加 1）、來源回合 >=5 加 1。這些是可核對的蠕動代理指標，並非最優解難度或 AI 必敗的判定。第 8／12 層各約 19.2%，第 15 層約 15.4%，其他四場各約 11.5%；一般關卡仍有機會。所有配置均取戰鬥前的牌組與資源，來源該場獎勵不提前加入。兩項權重測試通過，預覽核對成功；權重變更後尚未另外呼叫模型重打。
