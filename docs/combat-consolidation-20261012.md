# 戰鬥計算與接手流程整理

分支 `codex/consolidate-combat`，從 Claude 最新主線 `e38f3f0` 建立獨立 worktree；未改共享主工作區、合併或部署到面板。本次處理 Claude 對話列出的四處整併。

## 共用文字解析與指定序列模擬

`combat/text.py` 統一格擋、單次／多段傷害與能量數字的文字解析。牌組概況與考題的描述統計共用它。文字提到傷害不代表所有效果可模擬：搜尋仍核對卡牌 ID、完整描述、目標與費用，不因解析出數字就放行未知機制。

`combat/search.py` 的 `search_turn` 與新 `evaluate_sequence` 共用同一個 `_turn` 模擬核心。前者枚舉方案；後者只走指定順序與原始手牌索引，不偷偷換成更好的方案。兩者共用逐擊取整、痛擊先傷害後易傷、充能球、神氣制勝、音叉、死亡觸發、覆甲與扣環等既有支援。指定序列未結束回合時，不計充能球被動、不宣称敵人回合承傷。

考題評分移除自己累加目標傷害與充能球的 `planned_kills` 實作，改走共用模擬；保留函式入口，但未知方案回 None。`kills_all`、`unblocked`、`dies`、實際 `damage`／`block` 只有完整支援才能給數字；描述提到的粗略數值另外放 `described_damage`／`described_block`，不作擊殺證據。

藥水序列目前尚未納入共用模擬，回 `unsupported_plan_potion`；抽牌、隨機、多目標閃電或未知狀態也保留原有拒絕理由。這是評分能力限制，不是 AI 答錯的證據。考試遇到需要數字但結果為 None 會明確列「無法判定」，包含 `dies != true`，不能因 None 不等於 True 就通過。報告將無法模擬的完整回合另計；死亡比例只用已判定回合作分母。

## 決策與等待流程

`Controller.local_decision` 明確維持既有優先序：已選候選／程式優先隊列、強制操作、搜尋、休息、路線、普通隊列；依序詢問來源，命中後不詢問後續來源。`adopt_model_plan` 集中模型回覆後的路線／購物／出牌計畫建立。`run` 保留讀局面、範圍、執行、過期與重複操作保護；沒有改正常模式的 AI 介入門檻，也沒有新增模型呼叫。

`wait_for_change` 按是否有完整布林佇列訊號分流。新版等待 `running=false`、`queue_empty=true` 與動作後局面變化；需要玩家選牌的暫停佇列可返回。戰鬥中訊號消失或一直沒有動作完成證據時停止，戰鬥結束轉獎勵時允許訊號正常消失。新版路徑不再執行干癟之手改費猜測或安靜窗口。

舊 mod／舊紀錄沒有 execution 時，觀察手牌、延遲改費與安靜窗口集中在 `wait_for_legacy_change`。沒有證據能全面移除舊版相容需求，因此保留此獨立 fallback；不是把新版也改成只看到移除手牌就繼續。模組目前的訊號來自 ActionQueueSet 與 ActionExecutor，本次沒有修改 C# 或重啟遊戲。

## 戰鬥識別與驗證

`core/screens.fight_key` 共用 `in_fight` 的畫面判斷；模型調度、對話同步共用此函式。刪除 `sync_combat` 的兩段選牌畫面特例。戰鬥內手牌／卡池／組合／遺物選擇維持對話；同樓層回合倒退仍關閉舊對話；商店選牌不算戰鬥。單畫面範圍也核對樓層，避免同回合數的新戰鬥被當成舊畫面。

223 項離線 Python 測試通過，新增案例驗證：指定順序與最優顺序結果不同、未結束回合不計球被動、重複牌／錯誤目標拒絕、遺物按剩餘手牌算格擋、未知效果不能通過生存檢查、戰鬥選擇畫面的共同身份、佇列訊號中途消失與無完成證據時停止。既有干癟之手延遲、長時間忙碌佇列、暫停選牌、候選擁有隊列、模型對話等測試仍通過。

零模型離線檢查 40 題現有戰鬥題的原始答案，評分沒有例外：6 題可走指定序列模擬；10 題未知遺物、7 題未知敵人狀態、7 題未知手牌觸發、6 題藥水序列、2 題無法執行完整序列、2 題隨機球目標。原始比較在忽略的 `build/consolidation-score-audit.json`。尚未擴充那些未知機制，也未重新呼叫模型、宣稱舊考試分數或新勝率。本次未做新的實機連續出牌驗證。

## 效果表整理

`combat/card_effects.py` 集中目前支援的 19 個卡牌 ID（包含五角色打擊／防禦）的規則：目標、完整描述樣式、數字擷取與效果欄位。`card_move` 統一核對費用、星星費用、原始索引與完整文字後產生 Move；搜尋、候選與考題共用。普通傷害、格擋、多段、先傷害後易傷，以及原有充能／激發和兩種 kill-only 牌不再各寫一段 ID 分支。效果表只描述既有模擬核心能執行的機制，不是加入名稱或傷害數字就能支援所有新牌；痛擊與逐擊取整的順序仍由共用核心執行。

`combat/relics.py` 的 `RELIC_RULES` 集中九種取得／開場效果、四種條件效果與音叉：說明、時機、觸發事件、效果、量與門檻。原有 ENTRY_RELICS／CONDITIONAL_RELICS 改為相容視圖，描述只存一處。搜尋以效果種類判斷抽牌／隨機改費界線；扣環格擋與音叉的每十張技能加七格擋，讀同一份參數，隊列更新計數也共用。覆甲／模糊仍是狀態效果；未知遺物、隱藏使用旗標與隨機效果的保護保留。歷史上只按 ID 放行的 PASSIVE_RELICS 未藉本次重構擴大或假裝重新驗證。

比較基準 `8d50d97`：209 個卡牌輸入變體（原文、改費、錯誤目標、星星費、無效索引、附加抽牌、未知 ID 等）產生相同 Move／拒絕結果；204 個局面（既有考題、受控實機快照、各支援卡牌配遺物案例）的搜尋結果與候選完全相同，零差異。比較記錄在忽略的 `build/effect-registry-comparison.json`。全套 228 項離線測試通過；新案例核對各角色起始牌、完整文字拒絕、痛擊後雙重打擊取整、kill-only 限制，以及音叉技能計數與格擋。沒有模型呼叫或新的實機驗證；沒有新增機制支援或主張省下額度。

## 第一批機制擴充：出牌與消耗格擋

從此前兩批診斷戰鬥紀錄去重後讀取 1,381 個穩定玩家局面（排除 duplicate 關卡）。余像出現在 383 個局面，小刀在手牌出現 291 次；精准 212 個、無懼疼痛 73 個。這些是紀錄出現次數，不是可省呼叫數。

核對目前安裝遊戲實作 AfterimagePower、FeelNoPainPower、AccuracyPower、Shiv，以及 CombatManager 回合結束時序後加入：

- 已存在的余像按每張支援牌加格擋，不受衰弱影响，也不把施放余像當成其首次觸發。能力牌施放仍不在本批搜尋範圍。
- 小刀支援單一敵人傷害與打出後消耗；精准已包含在 API 手中小刀的傷害描述，僅驗證狀態，不再加一次。扇形飛刀改成全體目標仍拒絕。
- 已存在的無懼疼痛按支援牌的消耗加格擋；余像、音叉與神氣制勝可以同時計算。其他消耗觸發（例如黑暗之擁抽牌）仍由未知狀態保護擋下。
- 已驗證的不能打出／虛無牌（進階之災、笨拙、晕眩）結束回合消耗時可觸發無懼疼痛；傷口不算。扣環先數手牌、充能球被動之後再處理這些虛無消耗。未知或帶額外效果的狀態牌仍拒絕，沒有模擬灼傷或污染。
- 模型的 card_trigger_counts 改用每張牌／每次消耗格擋和「已含在傷害描述」的數值摘要；只有完整吻合的狀態描述才移除重複原文。模型承傷摘要也納入已知的虛無消耗格擋。

235 項離線測試通過，包含衰弱下的獨立格擋、精准不重複加傷、小刀消耗、扣環／虛無時序、音叉與神氣制勝疊加，以及未知抽牌、改過描述與全體小刀拒絕。`tests/fixtures/onplay-block-recorded.json` 擷取舊紀錄中單張小刀打出前後的余像格擋 18→19；此測試只驗證已知觸發的格擋差，不冒充整場已完全模擬。本批未重新操作遊戲或呼叫模型。

固定舊局面重播相對 `c27c079`：unknown_player_status 從 886 降至 779，但多數隨後仍遇到接續復活、人體蜂房、紙傷難愈等未知敵人效果或未支援手牌。完整程式局面仍為 63 個（56 supported_turn、7 direct_win），新增完整程式決策 0，原先支援局面沒有變成 fallback。這一批增加數值摘要與機制支援，尚未證明省下實際呼叫；下一步應依新的拒絕原因核對敵人效果，而非移除保護。原始統計與比較在忽略的 `build/coverage-states.json`、`build/onplay-block-replay.json`。

## 三場純程式實機（2026-10-12）

使用者開啟遊戲後確認主選單、面板 busy=false，使用本分支的 `tools/takeover_log.py --one-fight --program-compare --steps 80`。三場皆 A0／第 5 層兩隻噬屍蛞蝓、80 HP、無藥水，各自新的亂數；五張人工診斷牌組，並非全隨機遭遇、完整冒險或來源玩家原牌組的勝率比較。這次受控回歸測試重用已知敵人，未改之前隨機池排除已測遭遇的設定。

| 鐵衛 | 無懼疼痛＋、小刀、雙重打擊＋、打擊＋、防禦＋；程式固定先打能力 | 3 | 80→74 | 9 | 勝利，但原版結束等待誤停 |

鐵衛加入小刀是測試消耗互動的跨角色診斷配置，不宣稱這是一般抓牌可得的牌組。能力啟動屬固定設定（額外 1＋2 次操作），不是搜尋器自主選擇能力時機。其餘全部程式決策，沒有人工續打或模型介入。24 次接手操作＋3 次設定均成功；model／model_input／model_call 紀錄均為 0。結束回合的五次可核對承傷：0、6、5、0、0，全部吻合搜尋預測；沒有戰後回血遺物。

實機發現 ActionExecutor／execution 在 CombatManager 結束時先消失，而房間仍短暫回 monster，battle 可能為 null 或整個省略。原本等待器將此視為戰鬥中訊號遺失，導致前兩場殺死最後敵人後誤停；稍後重新讀取均已是 rewards。保留原始報告與退出畫面，summary 另外註記 completion_wait_interrupted 與晚一步核對的獎勵畫面，不冒充三場都無中止。

修正：若此前有有效 execution，維持新版等待路徑；monster／elite／boss 暫無 battle 時只等待，不送下一個操作，待真正轉獎勵再返回。仍有 battle 的戰鬥中訊號消失照常停止，超時也停止。第三場確認缺欄位過渡後可正常到 rewards。新增 null／缺欄位過渡測試，連同原有訊號消失、忙碌超時與選牌暫停共 236 項測試通過。

原始配置、固定設定、逐步紀錄、summary、final-after-transition 與五次承傷核對在忽略的 `vakuu/button-runtime/lab/pure-three-4b92d832/`。遊戲留在第三場獎勵畫面，沒有領獎勵或活躍 AI 控制器；面板仍未切換到本分支。
